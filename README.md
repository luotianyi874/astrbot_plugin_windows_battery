# Windows 设备电量 / Windows Battery

在 AstrBot 里一条指令查看**运行 AstrBot 的那台 Windows 电脑**还剩多少电；
回复内容可以自定义，电量低于阈值时还会**自动提醒你充电**，提醒文案同样可以在插件配置里改。

> 只对 **Windows 本机部署** 的 AstrBot 有效。如果 AstrBot 跑在 Linux 服务器或 Docker 里，
> 读到的是那台机器的状态（通常没有电池），指令会提示读不到电量。

## 使用

唤醒词 + `设备电量`，例如 AstrBot 的唤醒词是 `/` 时发送：

```
/设备电量
```

机器人回复（默认模板）：

```
小明，你的设备电量还有87%。
```

### 指令一览

| 指令 | 作用 |
|---|---|
| `/设备电量` | 查询当前电量 |
| `/设置电量模板 <模板>` | 临时修改查询回复模板 |
| `/设置电量用户名 <名字>` | 临时修改文案里的称呼 |
| `/电量配置` | 查看当前称呼、模板、提醒设置 |
| `/电量提醒绑定` | 把当前会话加入低电量提醒 |
| `/电量提醒解绑` | 把当前会话移出低电量提醒 |
| `/电量提醒状态` | 查看提醒开关、阈值、订阅会话、上次提醒时间 |
| `/电量提醒测试` | 立刻发一条测试提醒（仅管理员） |

- 别名：`设备电量` = `电池电量` = `电量` = `battery`；`电量提醒状态` = `电量提醒`。
- 指令前置的 `/` 以 AstrBot 里配置的唤醒词为准，换成别的唤醒词也照样能用。
- 模板、称呼填 `默认` 可以还原成插件配置页里的值。

## 低电量自动提醒

插件加载后会启动一个后台任务，默认每 60 秒读一次电量。当电量**小于或等于提醒阈值**时，
自动向已订阅的会话推送提醒，例如默认文案：

```
小明，你的设备电量还有20%，请及时充电。
```

### 三步开用

1. 在想收到提醒的会话里发一次 `/设备电量`（默认会自动订阅当前会话），或者发 `/电量提醒绑定`；
2. 打开 WebUI → 插件 → **Windows 设备电量** → 配置，按需要改「低电量提醒阈值」和「低电量提醒内容」；
3. 发 `/电量提醒状态` 确认「已开启」且当前会话「已订阅」，再用 `/电量提醒测试` 预览效果。

### 提醒规则（防打扰）

- **只提醒一次**：电量第一次掉到阈值及以下时提醒一次，之后不会每轮检测都发；
- **重新武装**：电量回升到「阈值 + 5%」以上之后，才允许下一次提醒，避免在阈值附近反复打扰；
- **重复提醒**：如果一直没充电、电量持续偏低，默认每 30 分钟再提醒一次；填 `0` 表示只提醒一次；
- **仅在使用电池时提醒**：默认开启，插着电源时不催你充电（可以在配置里关掉）；
- 提醒发送成功或失败都会写 AstrBot 日志，失败会在下一轮检测自动重试。

### 资源占用：不是死板地每 60 秒读一次

「检测间隔」只决定**电量掉到阈值附近时**的读取频率，其余情况会自动放慢，避免多余唤醒：

| 当前状态 | 读取电量的频率 |
|---|---|
| 关掉了提醒 / 还没有任何会话订阅 | **完全不读电量**，只每 60 秒看一眼配置 |
| 插着电源（且开启「仅在使用电池时提醒」） | 5 分钟一次，只为发现「拔电」 |
| 电量还比阈值高 20% 以上 | 5 分钟一次 |
| 电量比阈值高 0~20% | 2 分钟一次 |
| 刚掉到阈值、正在等重复提醒或回血 | 先按「检测间隔」（默认 60 秒），提醒后降到 2 分钟一次 |
| 读不到电池（台式机 / 非 Windows） | 5 分钟一次 |

配一个首次订阅：任何会话第一次发「设备电量」或「电量提醒绑定」时，后台任务会被**立即唤醒**，
不用等下一个周期才开始监测。

为什么用轮询而不是系统事件：Windows 的 `RegisterPowerSettingNotification` 需要一个窗口消息循环
（AstrBot 是纯 asyncio 无窗口程序），要额外引入线程/消息泵，稳定性风险大于收益。
而每次读取就是一次 `GetSystemPowerStatus` 系统调用（微秒级，不读磁盘、不发网络请求），
在上表的放慢策略下开销可以忽略。

### 提醒发给谁

按顺序合并去重后推送：

1. 配置页里的「固定提醒会话」（`push_targets`，可选，一般不用填）；
2. 用 `/电量提醒绑定` 绑定、或查询电量时自动订阅的会话（保存在插件数据目录）。

不想让某个群收到提醒，在群里发一次 `/电量提醒解绑` 即可；也可以在配置里关掉「查询电量后自动订阅当前会话」，
改成只手动绑定。

## 自定义文案

**回复**和**提醒**都有各自的模板，都支持占位符，都可以在插件配置页里改。

回复模板（配置项「电量查询回复模板」）：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{username}` | 称呼 | 小明 |
| `{percent}` | 电量百分比（纯数字） | 87 |
| `{state}` | 供电状态 | 电源已接通 / 使用电池 |
| `{sender}` | 发送消息的人的昵称 | 小明 |

提醒模板（配置项「低电量提醒内容」）：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{username}` | 称呼（主动提醒没有发送者，不会用昵称兜底） | 小明 |
| `{percent}` | 当前电量百分比 | 20 |
| `{threshold}` | 触发提醒的电量阈值 | 20 |
| `{state}` | 供电状态 | 使用电池 |
| `{time}` | 提醒时间 | 2026-10-28 08:30:00 |

默认值：

- 回复：`{username}，你的设备电量还有{percent}%。`
- 提醒：`{username}，你的设备电量还有{percent}%，请及时充电。`

模板里的其它花括号不会被当成格式化占位符，写坏也不会报错。
称呼的取值优先级：`设置电量用户名` 指令 > 配置页「称呼」> 发送者昵称（仅查询回复）>「当前计算机」。

## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 称呼 / 用户名 | string | 空 | 文案里的 `{username}` |
| 称呼留空时使用发送者昵称 | bool | 开 | 只影响查询回复 |
| 电量查询回复模板 | text | 见上 | 查询回复的内容 |
| 允许用指令临时修改称呼和回复模板 | bool | 开 | 关掉后只能改配置页 |
| 开启低电量自动提醒 | bool | 开 | 提醒总开关 |
| 低电量提醒阈值（%） | int | 20 | 电量 ≤ 该值时提醒 |
| 低电量提醒内容 | text | 见上 | 提醒的文案 |
| 仅在使用电池时提醒 | bool | 开 | 插电时不打扰 |
| 检测间隔（秒） | int | 60 | 距阈值很近时的读取间隔，可 10-3600 |
| 重复提醒间隔（分钟） | int | 30 | 0 表示只提醒一次 |
| 查询电量后自动订阅当前会话 | bool | 开 | 省去手动绑定 |
| 固定提醒会话 | text | 空 | 格式 `平台:消息类型:会话ID`，逗号或换行分隔 |

改完配置下一轮检测就会生效，不用重启 AstrBot。

## 在 QQ 官方机器人上使用

QQ 官方机器人（`qq_official`）对消息和推送有自己的限制，插件已经做了适配：

- **唤醒前缀可能没被剥离**：某些配置下框架不会把 `/设备电量` 里的 `/` 去掉，
  标准指令因此匹配不到、表现为「发了指令没反应」。插件内置了兜底匹配，
  `/设备电量`、`／设备电量`、`电量` 在这些情况下同样可用；
- **群聊 / 频道消息可能残留 `@` 标记**：插件会先剥掉 `<@!openid>`、`<qqbot-at-user ...>` 之类的标记再识别指令；
- **回复按纯文本发送**：QQ 官方机器人对原生 markdown 有权限要求，插件显式按纯文本发送，避免回复被平台拒收；
- **主动提醒受平台限制**：QQ 官方「主动消息」有配额，长时间没有和机器人互动的会话可能收不到自动提醒。
  这类失败会写进日志，并在下一轮检测重试；想稳定收到提醒，建议用 QQ 个人号（`aiocqhttp`）等支持主动消息的平台。

## 安装

1. 把整个 `astrbot_plugin_windows_battery` 文件夹放进 AstrBot 的 `data/plugins/` 目录；
2. 在 WebUI「插件管理」里找到它，点击**启用 / 重载**；
3. 缺少依赖时 AstrBot 会按 `requirements.txt` 安装 `psutil`，也可以手动 `pip install psutil`。

目录结构：

```
astrbot_plugin_windows_battery/
  metadata.yaml        # 插件元数据
  main.py              # 插件逻辑
  _conf_schema.json    # 插件配置页的字段
  requirements.txt     # 依赖：psutil
  README.md
  LICENSE
```

## 实现说明

- 电量优先用 `psutil.sensors_battery()`；psutil 缺失或异常时回退到 `ctypes` 直接调用 Windows 的
  `GetSystemPowerStatus`，不依赖第三方库；
- 两者都失败（台式机、没有电池、`BatteryLifePercent` 为 255 表示未知）时，回复会说明读不到电量；
- 非 Windows 系统会提示该插件仅支持 Windows；
- 低电量提醒在 `initialize()` 里用 `asyncio.create_task` 启动，`terminate()` 里取消并等待退出，重载插件不会残留任务；
- 后台任务是**惰性**的：没开提醒或没有订阅会话时一次电池都不读；有订阅后按「电量充足度」自适应放慢到 2-5 分钟一次，
  只有电量接近阈值时才用满「检测间隔」；`_add_subscriber` 会通过 `asyncio.Event` 立即唤醒任务；
- 提醒通过 `context.send_message(unified_msg_origin, MessageChain)` 主动推送；
- 订阅会话、是否已提醒、上次提醒时间等状态保存在 **插件数据目录**
  `data/plugin_data/astrbot_plugin_windows_battery/settings.json`，更新 / 重装插件不会丢；
- 不向插件自身目录写任何文件；
- 单次检测或单个会话发送失败都不会让后台任务退出。
